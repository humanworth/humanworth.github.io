How these were chosen

I surveyed the 2026 literature before writing this. Every obvious topic in AI security is saturated — MCP tool poisoning, agent memory poisoning, RAG membership inference, prompt injection and jailbreaking all have multiple surveys, competing attacks, and public benchmarks as of this year. Pitching a topic loses. The openings that remain fall into three categories, and all six directions sit in one of them.

A
Evaluation–reality mismatches
Defenses validated in configurations nobody actually deploys.
B
Compositions
Two well-studied things whose interaction nobody has studied.
C
Defense and detection
Attacks vastly outnumber defenses; the 2026 agentic-security surveys name detection and containment as the field's largest gap.

Each direction still needs a proper related-work pass before we commit — this is a short survey, not a literature review, and this field produces a survey of anything within six months.

01

Deletion propagation in agentic systems

Flagship Gap A + B Public data only

The gapUnlearning verification is well developed for model weights. Nobody has mapped deletion across a deployed agentic stack. When a GDPR request removes a document from a RAG corpus, the content survives in derived embeddings, the ANN index structure, KV and prompt caches, the agent's summarised long-term memory, conversation logs, fine-tuned adapters, evaluation sets, and the memories of other agents that read it downstream. Data lineage here is unmapped, so "deletion" is unverifiable in exactly the systems regulators are about to audit.

First experiment
Build a reference RAG-plus-memory agent stack, plant canary documents, issue a deletion, then attempt extraction from each surface. Report a survival matrix.
Why us
The canary methodology is exactly the membership-inference toolkit from my thesis, pointed at a new target. Directly continues the lab's privacy line.
Venue
USENIX Security, PETS, or CCS.
Effort
Systems-heavy, modest compute. Good for a strong student with one year.
02

The deployment gap: defenses tested at FP32, shipped at INT4

Fastest to submit Gap A Public data only

The gapRecent work found INT8 quantization drops backdoor-defense detection rates to zero while attack success stays above 99%. That is one instance of a general pattern nobody has systematised: AI security defenses are evaluated on full-precision models and deployed on compressed ones.

First experiment
Six published defenses with public code — prompt-injection detectors, jailbreak filters, RAG poisoning defenses — re-evaluated across four real deployment transforms: quantization, distillation, LoRA stacking, prefix/KV-cache reuse. Measure detection rate and attack success across the grid.
Why us
No novel method required, so it converts directly into a submission. I see the deployment configurations that academic evaluations miss.
Venue
USENIX Security or ACSAC; a workshop version first if we want speed.
Effort
Mechanically straightforward, high reproducibility value. Ideal first project for a new student.
03

Cross-tenant leakage in shared vector infrastructure

Gap B Public data only

The gapQuery-based membership inference against RAG is crowded. Multi-tenant RAG is not — and it is how every enterprise actually deploys. Shared embedding indices, shared cache layers, shared rerankers.

First experiment
Two-tenant Qdrant or pgvector deployment; test whether tenant A's insertions are detectable through tenant B's query latency, recall distribution, or HNSW neighbour structure.
Why us
A classical side-channel attack wearing an AI hat — systems security methodology, with the distinguisher design coming from our MIA work.
Venue
USENIX Security, NDSS.
Effort
Needs careful measurement hygiene. Suits a student with a systems background.
04

Attacking continuously-retrained models

Gap B Synthetic data

The gapNearly all adversarial ML assumes a static victim. Production fraud and AML models retrain weekly on recent labelled data — including labels generated by the attacker's own past activity. Attacking a model that learns from your attacks is a control problem, not a one-shot evasion problem.

First experiment
Simulate on public synthetic transaction data (PaySim, IBM AML), implement a weekly retraining loop, and compare one-shot evasion against a multi-round attacker that deliberately shapes the retraining distribution.
Why us
I work on these systems and know how the retraining loop behaves in practice — the detail academic treatments get wrong. Uses no proprietary data of any kind.
Venue
USENIX Security, or AISec / FinNLP workshop first.
Effort
Self-contained simulation. Very good MSc thesis shape.
05

Emergent collusion among negotiating agents

Gap C No data needed High visibility

The gapThe 2026 agentic-security surveys name multi-agent collusion as severely under-studied, empirically and theoretically. Prior algorithmic-collusion work used reinforcement learning agents; LLM agents coordinate in natural language, which makes the collusion legible and directly measurable for the first time.

First experiment
Repeated Bertrand or auction game with three to five LLM agents; measure price convergence against the Nash baseline and inspect reasoning traces for coordination the agents were never instructed to perform.
Why us
Cheap to run, no dataset, and it opens venues beyond security. Financial regulators are already asking this question.
Venue
AIES, FAccT, or ACM AFT.
Effort
Low compute, high write-up quality required. Strong press potential.
06

Minimum sufficient telemetry for agent compromise detection

Gap C Benchmark output

The gapEveryone publishes agent attacks; a 2026 enterprise survey found 95% of security leaders doubt they could detect or contain a compromised agent. There are vendor playbooks listing forensic artifacts, but no empirical answer to the real question: which subsets of telemetry are necessary and sufficient to detect which attack classes, and what is irreducibly invisible?

First experiment
Construct a labelled dataset of benign versus compromised agent traces across attack classes; ablate telemetry subsets — prompt history, retrieved context with provenance, tool-call sequence, identity assumptions, output traces — and report achievable detection rates per subset.
Why us
The output is a public benchmark, the highest citations-per-effort artifact available in this field and a durable asset for the lab.
Venue
NeurIPS Datasets & Benchmarks track, RAID, or ACSAC.
Effort
Data-generation heavy, conceptually clean. Well suited to two students working together.
